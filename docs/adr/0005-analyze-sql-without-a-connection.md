# Analyze SQL without a connection

`analyze(sql)` must work from the SQL Program alone, with no database connection. Every feature has a connectionless path. When the SQL alone does not settle something, such as an unqualified column that more than one source without a `CREATE` could own, analysis emits a warning Diagnostic that names the ambiguity and how to remove it (declare the table, or qualify the column), and treats the affected facts as unknown. It never guesses: a guess that happens to be wrong would read to the author as a proof. Results stay sound, and the only loss is completeness. When a connection is given (`analyze_database`), the catalog resolves the ambiguity and analysis uses the resolved answer. A connection can only turn UNKNOWN into PROVED; it never changes what the SQL alone proves.
