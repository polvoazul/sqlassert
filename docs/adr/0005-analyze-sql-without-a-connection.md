# Analyze SQL without a connection

`analyze(sql)` must work from the SQL Program alone, with no database connection. Every feature has a connectionless path. Whenever a connection would have helped, analysis emits a warning Diagnostic, even when the result is otherwise fine. Examples: a table with no `CREATE` (its keys, nullability and column types are unknown), a column whose type decides a comparison, or an unqualified column that more than one such table could own. The warning names what is missing and how to supply it: declare the table, qualify the column, or pass a connection. It is reported once per missing object, not once per use. Affected facts are treated as unknown. It never guesses: a guess that happens to be wrong would read to the author as a proof. Results stay sound, and the only loss is completeness. When a connection is given (`analyze_database`), the catalog resolves the ambiguity and analysis uses the resolved answer. A connection can only turn UNKNOWN into PROVED; it never changes what the SQL alone proves.
