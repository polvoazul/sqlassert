Fan Trap

Multiple refunds can make the same payment count more than once.

fan-trap.sql

1CREATE TABLE orders (id INT PRIMARY KEY);2CREATE TABLE payments (id INT PRIMARY KEY, order_id INT, amount INT);3CREATE TABLE refunds (id INT PRIMARY KEY, order_id INT);4 5SELECT o.id, SUM(p.amount) AS paid6FROM orders o7JOIN payments p ON p.order_id = o.id8JOIN refunds r ON r.order_id = o.id9GROUP BY o.id;

Terminal output excerpt

$ sqlassert suggest fan-trap.sql

Fan trap · line 9

SUM(p.amount) reads rows that JOIN refunds AS r may repeat: the join is not proved to repeat rows of only one input (fan trap), so a value may be counted more than once

INNER JOIN

Every order has a customer, so the outer join can be simplified.

inner-join.sql

1CREATE TABLE customers (id INT PRIMARY KEY, name VARCHAR);2CREATE TABLE orders (3    id INT PRIMARY KEY,4    customer_id INT NOT NULL REFERENCES customers(id)5);6 7SELECT o.id, c.name8FROM orders o9LEFT JOIN customers c ON c.id = o.customer_id;

Terminal output excerpt

$ sqlassert suggest inner-join.sql

INNER JOIN · line 9

every left row matches exactly one right row, so the LEFT JOIN pads nothing: write JOIN
-LEFT JOIN customers c ON c.id = o.customer_id;
+JOIN customers c ON c.id = o.customer_id;

Redundant Join

The coupon contributes no columns and cannot multiply orders.

redundant-join.sql

1CREATE TABLE orders (id INT PRIMARY KEY, coupon_id INT);2CREATE TABLE coupons (id INT PRIMARY KEY);3 4SELECT o.id5FROM orders o6LEFT JOIN coupons c ON c.id = o.coupon_id;

Terminal output excerpt

$ sqlassert suggest redundant-join.sql

Redundant Join · line 6

at most one match per row and no column of coupons AS c is used outside its ON: delete the join
-FROM orders o
-LEFT JOIN coupons c ON c.id = o.coupon_id;
+FROM orders o;
